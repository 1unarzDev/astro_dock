REAL THRUSTERS — ODROID ONLY; clear/submerge propellers, secure boat first
  ros2 run mhseals_hardware thruster_pwm_node   # cmd_vel -> native PWM/GPIO
  ros2 run mhseals_hardware keyboard_control   # keyboard -> cmd_vel
  ros2 run mhseals_hardware thruster_test      # direct physical-output PWM TUI
  ros2 run mhseals_hardware boat_test          # guided tests + sensor bags
  ros2 run mhseals_hardware remote_controller  # RCIn -> cmd_vel
  Run ONLY ONE command publisher; do not mix navigation/RC/keyboard control.
  Keyboard: WASD/arrows move, +/- speed, Space neutral, X exit.
  Release-aware terminals stop on key-up. Ordinary SSH uses repeat timeouts:
  initial 0.65 s grace, then 0.15 s. Space stops without waiting for timeout.
  boat_manual is a compatibility alias for keyboard_control.

PERSISTENT HARDWARE SETTINGS (pins, MOSFET, channel map, mixer, timeouts)
  Defaults: mhseals_hardware/config/default.yaml inside the Python package.
  Override: ~/.config/mhseals/hardware.yaml
  Prefer a mounted workspace config to survive container recreation:
    export MHSEALS_HARDWARE_CONFIG="$ROS_WS/config/hardware.yaml"
  Create/copy the YAML before exporting the path; missing explicit files fail.
  boat_test --identify-thrusters pulses outputs and saves the resulting map.
  boat_test --mosfet-line 28 --save-config persists a CLI pin override.
  Both boat_test and thruster_test accept --config /absolute/hardware.yaml.
  thruster_pwm_node accepts --ros-args -p config_file:=/absolute/hardware.yaml.
  Stop controllers before changing pins. No Pico is used.

MHSEALS_NAV (JAZZY WORKSPACE)
  Simulation is the default; state sim explicitly on a real boat:
    ros2 launch mhseals_nav robot.launch.py sim:=true
    ros2 launch mhseals_nav robot.launch.py sim:=false fcu_url:=serial:///dev/ttyACM0:57600
  ODROID: suppress drivers hosted on the Jetson:
    ros2 launch mhseals_nav robot.launch.py sim:=false sensors_ignore:=camera,lidar fcu_url:=serial:///dev/ttyACM0:57600
  JetPack 6 sensor host (no MAVROS):
    ros2 launch mhseals_nav sensors.launch.py sim:=false
  sensors_ignore accepts camera,lidar; it skips drivers, not localization
  consumers. Missing topics can still stall navigation. It does not disable
  thrusters and is not a substitute for sim:=true.
  Inspect options: ros2 launch mhseals_nav robot.launch.py --show-args
  Minimal telemetry: ros2 launch mhseals_nav boat_test.launch.py

CAMERA / DISTRIBUTED ROS
  Both Jetsons: ros2 launch zed_wrapper zed_camera.launch.py camera_model:=zed2i
  Check data, not just topic presence: ros2 topic hz <image-topic>
  Legacy ZED 4 and current ZED 5 have different topic/custom-message layouts.
  Jazzy uses ROS_DOMAIN_ID=42; legacy Foxy uses 142. Keep them separate:
  direct Foxy/Jazzy DDS discovery crashed legacy nodes in boat testing.
  Use an explicit cross-version bridge, not merely matching domain IDs.
  JPEG preview without shared DDS (see docs/camera-preview.md):
    Jetson: astro-camera-preview serve --bind <boat-LAN-IP>
    Browser: http://<boat-LAN-IP>:8088
    Jazzy laptop: astro-camera-preview receive http://<boat-LAN-IP>:8088
  The ZED camera launch must also be running. Preview is lossy, 5 Hz by default,
  no CameraInfo/TF/depth; use it for debugging, not navigation inputs.
  Diagnostics: .devcontainer/device-diagnostics.sh; sudo -E ZED_Diagnostic -aio

PACKAGES
  Host prerequisite: run ./setup.linux.sh --components clock on the HOST.
  Containers inherit host time; check timedatectl status on each computer.
  Optional boat NTP: ASTRO_NTP_SERVER=<server> ./setup.linux.sh --components clock
  Either Jetson: sudo -E astro-ros-install topic_tools
  Tries distro debs first, then builds missing ROS dependencies into
  /opt/astro-extra. Open a new shell afterward. Source compatibility is not
  guaranteed across releases; failures are not ignored.
  Persist in images: edit .devcontainer/jetson-jp5-packages.txt or
  jetson-jp6-packages.txt and rebuild. Core uses .devcontainer/apt-packages.txt.
  Ad-hoc installs disappear when the container is recreated.
